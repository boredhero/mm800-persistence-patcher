# Custom animation JSON schema version 1

## Document

The root is an object with these fields:

- `version`: required integer 1.
- `strict_palette`: optional boolean, default false. True requires `palette`.
- `loop`: optional boolean, default false. True restarts the timeline from its
  explicitly encoded initial frame.
- `end`: optional `hold` (default) or `off`, used only when `loop` is false.
  `hold` keeps the final frame; `off` displays 45 zero RGB bytes.
- `palette`: optional object of unique names to `#RRGGBB` colors.
- `frames`: required object. Each value is either `{"fill": color}` or
  `{"zones": [15 colors]}`. Zone order is the existing stock order.
- `timeline`: required nonempty array of `{"frame": name, "duration_ms": n}`.
  Names may repeat with different durations. Nested loops are not supported.

Colors are `#` followed by exactly six hexadecimal digits. Named frame and
palette references must exist. Duplicate keys at every object level, invalid
references, non-integer durations, zero/negative durations, booleans used as
integers, and unknown fields are errors.

Initial parser limits: 16 MiB input, 4,096 frame declarations, 65,536 timeline
entries, 4,096 distinct RGB values, and total declared duration below 2^63 ms.
Binary duration entries are split at `0xffffffff` ticks without changing time.
Smaller compiled-budget checks happen after optimization, not a hard-coded frame
limit.

## Palette behavior

Names are conveniences; literal colors are always allowed. With a declared
palette, the compiler resolves all colors and warns about RGB values absent from
that palette. A literal matching any declared RGB value is inside it. Warnings
are grouped by RGB value, include occurrence count and representative
`frame/zone` locations, and become errors when `strict_palette` is true.

Without a declared palette, exact colors are discovered without warning. Duplicate
RGB values share one palette entry. Unused declared entries and unused frames are
removed during compilation. No color is silently changed.

## Lossless normalization

1. Resolve every timeline frame to exact 45 RGB bytes.
2. Deduplicate identical displayed frames in first-use order.
3. Merge consecutive entries displaying the same frame by adding durations.
4. Apply target timing only with explicit user permission. Default `exact`
   requires each merged duration to be a multiple of 34 ms. `round` explicitly
   converts each to the nearest 34 ms, minimum 34 ms, and reports both durations.
5. Split durations larger than `0xffffffff` ticks without changing total time.

Frame IDs and palette indices are assigned deterministically in first-use order.
Finite animations use the declared end behavior. Loops restart from the encoded
initial frame, never from stale final-loop RAM.

## Brightness and independent zone tracks

A track document uses `duration_ms`, `tracks`, and the shared `version`, `loop`,
`end`, `brightness`, `strict_palette`, and `palette` fields. Each zone may have
one track containing `zone`, `color`, `interpolation` (`hold` or `linear`), and
ordered `keyframes` with `time_ms` and `brightness`. Unspecified zones are off.
Duplicate zones, unsorted times, missing endpoints, invalid colors, and invalid
brightness are errors.

Brightness is a finite JSON number in [0, 1]. Zero is off; one preserves the base
color. NaN, infinity, and out-of-range values are rejected. Internally:

```text
gain = round(brightness * 65535)
output = round(base_channel * zone_gain * animation_gain / (65535 * 65535))
```

The multiplication uses a wide intermediate and original base colors, never a
previously rounded result. Animation-wide brightness defaults to 1. The separate
stock global brightness knob is not changed. Final physical output still uses
RGB bytes and the stock renderer, not a high-resolution per-zone register.

Palette checks apply only to base colors, before gain. Darker shades generated by
brightness are intentional and do not produce warnings. Base colors and rendered
colors are reported separately.

Exact track duration must be a multiple of 34 ms. `--timing round` explicitly
rounds the duration and every keyframe time to 34 ms, merging duplicate times.
Linear interpolation uses fixed-point gains between keyframes; hold jumps at the
next keyframe. Loop restart uses the first track frame; finite end uses the
final displayed frame or `off`.

### Adjacency and lit limits

Optional `adjacency` is an explicit array of zone pairs. No physical map is
inferred. Adjacent zones may not both have nonzero stock-rendered RGB at any
sampled tick or across the loop boundary. `max_lit_zones` optionally limits the
number of simultaneously lit zones. The fireflies generator requires an explicit
graph and uses off endpoints and dark gaps to enforce the constraints.

The `fireflies` host command takes a deterministic seed, duration, palette,
brightness, peak range, maximum simultaneous zones, and graph. It emits ordinary
track JSON, not a scripting engine or firmware randomness. The same seed and
parameters reproduce the same document.
